# Stage 8 — Deterministic Pythagorean Numerology

Related: [[02_ARCHITECTURE]], [[05_DECISIONS]], [[06_API_CONTRACTS]], [[07_TEST_STRATEGY]].
This is the project's symbolic calculation convention, not a scientifically validated measurement
or objective truth. Numerology has no single universal convention; the exact choices below define
this API. No interpretation, storage, network calls or frontend report is included.

## Input and privacy

`POST /api/v1/numerology/calculate` accepts `full_name` (strict string, 1–200 characters),
`birth_date` (valid Gregorian `YYYY-MM-DD`) and optional `target_year` (strict integer 1–9999 or null).
Numeric dates, datetime strings, numeric-string years and booleans are rejected. Extra fields and
malformed/nonobject bodies return `invalid_request`.

Future birth dates are rejected consistently with BirthProfile by a shared validation function.
Only the API admission layer supplies today's date using the overridable `validation_today`
dependency. The pure service does not read the clock. The admission date never supplies a target
year or affects any computed number. Given accepted inputs, output is always identical.

Missing or null `target_year` means `personal_year: null` and metadata `target_year: null`.
There is no implicit current-year default. Request names are never logged, persisted or echoed;
neither normalized names nor per-letter dumps appear in success/error responses.
All tracked test examples are synthetic, including the supplied convention examples below.

## Alphabet and normalization

One central letter table is used:

| Value | Letters |
| --- | --- |
| 1 | A J S |
| 2 | B K T |
| 3 | C L U |
| 4 | D M V |
| 5 | E N W |
| 6 | F O X |
| 7 | G P Y |
| 8 | H Q Z |
| 9 | I R |

ASCII case is ignored. Ç/ç→C, Ğ/ğ→G, İ/I/ı/i→I, Ö/ö→O, Ş/ş→S and Ü/ü→U.
NFC composition also supports decomposed Turkish characters. Whitespace, Unicode punctuation
(including hyphens/apostrophes) and separators are ignored. Only A–Z remain for calculation.
No transliteration of other alphabets or other accented Latin letters occurs; these and unsupported
combining marks produce `unsupported_name_characters`. Digits, emoji, symbols and non-whitespace
control characters produce `invalid_name`. Empty/punctuation-only names are invalid.

Vowels are **AEIOU**. **Y is always a consonant**, regardless of pronunciation.

## Formulas

Every non-null number has `raw_sum`, `value`, `is_master`. Core reduction repeatedly sums digits,
stopping at 1–9 or **11, 22, 33**, including intermediate masters: 29→11, 38→11, 44→8.
`is_master` is true only for those three terminal values.

| Number | Raw input to reduction |
| --- | --- |
| Life Path | Sum of every digit in YYYY-MM-DD; never reduce date components separately |
| Birthday | Day-of-month integer itself |
| Expression / Destiny | Sum of all normalized letter values |
| Soul Urge | Sum of vowel values; null when there are no vowels |
| Personality | Sum of consonant values; null when there are no consonants |
| Maturity | Life Path **value** + Expression **value**, not their original sums |
| Personal Year | Sum of birth month digits + birth day digits + explicit target-year digits |

Personal Year always reduces fully to 1–9, never preserves masters and always has `is_master: false`.
The expression raw sum equals the sum of vowel and consonant raw sums. Missing partitions count as
zero only when checking this identity; the API keeps them null.

Golden tests are written directly from these arithmetic rules, never generated by production code.

## Response and errors

Metadata contains `system: pythagorean`, `master_numbers: [11,22,33]`, `vowels: AEIOU`,
`y_is_vowel: false` and the explicit nullable `target_year`. The remaining fields are the seven
numbers in the table above. No birth date or name is returned.

HTTP 422 errors use `{"detail":{"code":"...","message":"..."}}`:
`invalid_name`, `unsupported_name_characters`, `invalid_birth_date`, `invalid_target_year`,
`invalid_request`. Validation input/context and internal exception details are not serialized.
If several schema fields fail, extra/malformed body errors take priority, followed by name,
birth date and target year. Character validation occurs after schema and future-date validation.

Run `docker compose run --rm backend python -m pytest -q` and
`docker compose run --rm backend python -m pip check`. Tests cover golden arithmetic, normalization,
reduction boundaries, privacy, clock injection, API shapes, repeatability and the partition invariant.
